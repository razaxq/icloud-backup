# iCloud 照片归档 · 飞牛 fnOS

从飞牛桌面打开应用，把一个或多个 Apple 账户的 iCloud 照片图库单向下载到 NAS 文件夹。原始媒体保持 Apple 提供的格式，并下载实况照片的配套视频、RAW/JPEG 伴随文件、编辑成片和可导出的 XMP 元数据。

界面采用浅灰底色、白色面板和单一蓝色强调色：顶部是当前任务与下次运行概况，下方为账户、运行记录和任务历史，在桌面和手机上分别排布。通知可在顶栏「设置」页面配置。Apple 要求验证时，验证卡片会出现在页面最上方。Inter 拉丁字体由 NAS 本地加载，中文使用系统字体，字体的 SIL Open Font License 随包提供。

## 安装

1. 在飞牛系统信息中查看 CPU 架构。Intel 或 AMD 使用 `dist/icloud-photos-<版本>-amd64.fpk`，64 位 ARM 使用 `dist/icloud-photos-<版本>-arm64.fpk`。应用通过统一网关接入飞牛桌面，需要 fnOS 1.1.3100 或更高版本，并依赖应用中心的 Python 3.12 运行环境（`python312`）。
2. 以管理员身份进入「应用中心 → 手动安装」，选择对应的 FPK。建议用飞牛的 HTTPS 地址打开应用，以保护浏览器到 NAS 之间传输的密码和验证码。
3. 安装时会创建共享目录 `icloud-photos/Photos` 作为默认保存位置。要保存到其他文件夹，在应用设置中为本应用授权该文件夹的读写权限即可，无需重启应用，正在进行的下载也不会中断。

从 0.1 或 0.2 升级会保留账户、计划、登录会话和已有照片。旧版的成功结果显示为「旧版未校验」，下一次运行会完整检查原件。设为「仅手动」的账户需要点击一次「开始下载」。

## 使用

- **添加账户**　在首页填写 Apple 账户、服务地区和保存目录。可点「浏览」在已授权的目录中选择，也可追加子文件夹名称。第一个账户默认使用安装时的共享目录，从第二个起会按账户和地区建议子目录。选择与其他账户相同的目录时需在页面明确确认。每个账户单独保存计划和登录会话，最多可添加 10 个。
- **首次下载**：点「保存并立即备份」，按提示输入账户密码，并在受信任设备上批准登录、输入验证码。收不到设备验证码时，可输入页面提示的字母改用短信接收。密码和验证码只在验证时交给下载器，不写入配置或运行记录。
- **自动备份频率**　每个账户可选择仅手动、每 5/10/15/30 分钟、每 1/6/12/24 小时或每 7 天备份。新账户默认每小时备份。多个账户依次运行，每次任务结束后开始计算该账户的下次运行时间。
- **快速检查**　点击「立即备份」或到达设定时间后，应用从最新项目开始逐项核对原件，每个图库或隐藏相簿连续遇到 100 个已完整归档的项目即可结束。首次备份、上次失败、距离上次完整扫描已满 7 天，或启用保留策略预览时，会在本次运行中完整扫描。完整扫描可补齐拍摄日期较早的新导入照片。
- **从 0.6.0 升级**　原有定时备份频率自动换算。已启用实时检测的账户使用原检测间隔，若同时启用了定时备份则取较短间隔。两者均关闭的账户继续仅手动备份。因等待验证而暂停检测的账户，可点击「立即备份」完成验证。旧版“每次完整扫描”使用上述统一扫描规则。
- **暂停与继续**　任务运行或等待验证时，可从「暂停」菜单选择暂停 30 分钟、2 小时或直到手动继续。暂停会停止下载器，已下载的文件和未完成的传输（`.icloud-work` 中的分段）都会保留；继续后跳过已完成的图库，从未完成的图库接着下载，最终作为一次任务记入历史，新增数量包含暂停前后的文件。暂停期间其他账户的计划任务会等待，点击「取消任务」可放弃已暂停的任务。暂停状态在服务重启后保留。
- **中断后继续**：应用停止、升级或 NAS 重启时，正在进行的任务会被记录为「已中断」，服务启动 1～2 分钟后自动继续，同样跳过已完成的图库。意外断电等情况下同样会自动继续，但同一账户连续 3 次意外中断后会暂停自动继续，以免反复出错。
- **查看结果**　卡片显示上次成功时间、下次运行时间和最近一次结果。「历史」保留最近 20 次任务。已知缺少原件、实况照片缺少原版视频、文件校验失败、iCloud 明确跳过项目或完整扫描返回的数量不足时，任务显示「未能完成」。已取得的文件保留在 NAS，上次成功时间保持原值。下次定时或手动运行会完整补查。「完成（有提醒）」用于共享图库未提供隐藏相簿等情况。意外停机后的历史数量以 ≥ 标注，表示中断前已确认写入的最低数量。
- **项目进度**　任务卡片显示去重的已检查项目、原件齐全项目、未完整项目和本次新写入文件数。同一实况照片计作一个项目。个人、隐藏和共享图库的文件均按原件规则核验。快速检查的计数仅覆盖本次访问的项目。账户卡片分别显示最近一次成功的快速检查和完整核对时间。
- **空间保护**　任务页显示目标盘最近测得的剩余空间。备份预留 1 GiB，写入前还要有足够空间放下本次媒体文件。在空间不足时自动暂停，按失败通知设置提醒，每分钟检查一次。释放足够空间后自动继续，也可点击「继续」立即检查。暂停期间已写入的文件及可续传的分段会保留。
- **验证 NAS 备份**　在账户旁点击「验证 NAS 备份」，选择完整扫描报告，点击「开始验档」。要验证还原副本，请输入飞牛已授权的还原目录，连同其中的 .icloud-archive 文件夹一起还原，再点击「读取报告」。验档只读取照片目录，在应用私有目录保存结果；无需 Apple 登录。页面列出前 100 个问题，可下载全部问题的路径与原因。结果仅覆盖所选报告中列出的项目。自 0.8.0 开始保留带日期的报告，升级时仍在盘上的旧完整报告也可选择。
- **通知**　在顶栏「设置 → 通知」中选择通用 Webhook（JSON）、Bark、ntfy、Telegram 机器人或 SMTP 邮件，可在 Apple 需要验证、任务未能完成、完成但有提醒或每次成功完成时收到提醒。通知只在没有人打开本页面时发送，账户名会部分隐藏。已保存的地址、令牌和邮件密码不会再显示在页面上。Apple 登录会话会定期过期，开启「需要输入 Apple 密码或验证码」通知后，可以及时发现备份停在验证这一步。等待输入密码最长 30 分钟，等待验证码最长 10 分钟，超时后可手动重试。
- **删除账户**：会同时删除该账户保存在 NAS 上的 Apple 登录会话，已下载的照片保留在原目录。
- **保留策略预览**　从 0.6.0 起保留所有 iCloud 原件。从 0.5.x 升级会关闭旧版清理设置，作废旧扫描进度。可在账户页选择预览全部已备份项目、按拍摄天数筛选或保留最新 X 项。完整核对成功后，任务结果显示候选数量。实况照片按一项计算，缺少拍摄日期的项目在按天数或数量预览时保留。
- **核对旧备份**　首次完整扫描会检查旧年/月目录和其中的 `.icloud-previous`，从校验值吻合的媒体复制原件，旧文件仍在原处。需要额外可用空间。任务结果显示归属待确认的旧文件数，保存目录下 `.icloud-archive` 中每个账户的 JSONL 报告列出路径、各项档案和策略候选。报告中的匹配仅表示文件内容相符。共享保存目录内也可能有其他账户的旧文件。
- **卸载**：卸载向导默认保留登录会话和设置，也可以选择一并删除。已下载的照片不会被删除。

如果 Apple 拒绝网页访问，请在受信任设备检查 iCloud 的网页访问设置。启用高级数据保护的账户可能还要在设备上批准临时访问。使用实体安全密钥登录的账户目前不支持。[Apple 关于 iCloud 网页访问的说明](https://support.apple.com/zh-cn/102630)

更换 ntfy 推送服务器时，如新服务器需要认证，请重新输入令牌。更换 SMTP 主机、端口、加密方式或用户名时，需要为新的连接重新输入密码。可在对应渠道的设置里移除已保存的令牌或邮件密码。

## 保存到 NAS 的文件

| iCloud 中的内容 | NAS 上的结果 |
| --- | --- |
| 照片、普通视频 | 请求原件，保留 HEIC、JPEG、DNG、MOV 等源格式。 |
| 实况照片 | 请求静态原件和原尺寸配套视频，例如 `IMG_0512_QWRFR00.HEIC` 与 `IMG_0512_QWRFR00.MOV`，可按共同的文件名配对。 |
| RAW+JPEG、编辑成片 | 额外请求 Apple 返回的 alternative 和 adjusted 版本，并保留可导出的 XMP 附属文件。 |
| 个人图库及隐藏项目 | 按拍摄日期归入 `年/月`。隐藏项目也出现在普通文件夹中，选择目录时请留意谁有读取权限。 |
| iCloud 共享照片图库 | 自动发现，分别写入 `共享图库/SharedSync-…/年/月`。可在账户设置中关闭。 |

每个图库项目独立保存到 `年/月/项目标识/版本标识/`，同一实况照片的静态图与视频在同一目录。项目标识来自已登录账户、图库范围、区域所有者和完整项目 ID；版本变动时另建目录。随文件保存的 `manifest.json` 记录项目身份、源文件名、版本、资源角色、大小及校验值。复制或还原备份时请一起保留媒体、XMP 和清单。编辑数据或 RAW 等资源缺失、遇到未知资源、只有预览图时，任务显示失败。

**离线核对还原**　从独立副本还原整个目录后，使用安装包内的 `bin/icloudpd --verify-archive <还原目录> <完整扫描报告.jsonl>`。该命令逐项检查资源、XMP 和原始报告记录的 SHA-256，可以离线运行。报告覆盖该次扫描列出的已核验项目。请将对应日期的报告与独立备份一起保留，以便核对当时的版本。旧版未认领文件仍需单独确认；云端记录已删除且缺少历史身份清单时，仅凭文件名或内容无法还原原有项目 ID。还原核对通过后，仍应在照片应用中试播实况视频并打开 RAW。

**原件判定**　对本次扫描遇到的每份媒体，按 Apple 返回的资源类型、字节数和文件校验值检查内容，包括 NAS 上已有的同名文件。新文件先在同一文件系统暂存，通过校验后再放入目标位置。同名旧文件如有差异，确认取得正确版本后会把旧内容保存在该版本目录的 `.icloud-previous` 中。完整扫描需要读取已有文件，大图库的首次升级检查可能耗时较长。

**低画质副本**　当原件缺失但 Apple 提供可验证的低画质版本时，保留的副本带 `-preview-` 和画质后缀，例如 `-preview-medium.MOV`。即使这份副本下载成功，当前任务也会显示失败。打开「运行记录」可查看缺的是照片原件、实况视频还是其他媒体。无法识别的校验格式同样算失败。

**可见范围**　应用根据 iCloud 照片网页接口提供的资源和实况标记作出判断。如果 Apple 同时省略配套视频及所有实况标记，应用无法把该项目与普通静态照片区分。传统「共享相簿」、「最近删除」、Photos 相簿结构和无损编辑历史不在扫描范围内。快速检查只覆盖本次访问的项目。新增数量按写入的媒体文件计，XMP 单独保存。[下载器文件命名规则](https://icloud-photos-downloader.github.io/icloud_photos_downloader/naming.html)

## 源码与构建

推送到 `main`、创建指向提交的 `v*` 标签或向 `main` 提交拉取请求时，GitHub Actions 会构建并校验 AMD64、ARM64 两个安装包，并使用 AMD64 安装包中的依赖运行离线测试。也可在工作流页面点击 **Run workflow** 手动构建。成功后，在该次运行的 **Artifacts** 下载 `icloud-photos-<版本>`，解压即可取得两个 FPK 和 `SHA256SUMS` 校验文件。[打开自动构建页面](https://github.com/razaxq/icloud-backup/actions/workflows/build.yml)

- `package/`：飞牛清单、生命周期脚本、安装与卸载向导、桌面入口。
- `web/`：网关服务（`server.py`，接口与静态页面）、账户状态与调度（`archive.py`，账户、计划、恢复、目录浏览）、通知发送（`notifier.py`）和中文界面（`static/`）。
- `worker/`：Apple 登录、图库扫描、实况识别、原件校验和文件写入。
- `tests/`：离线测试，`fake_icloudpd.py` 使用与上游 1.33.0 相同的提示文本和日志格式。

FPK 内置来自 icloudpd 1.33.0 的代码、原件校验模块和对应处理器的 CPython 3.12 依赖。源代码归档、依赖包和最终依赖目录均核对 SHA-256。安装完成后可直接运行。[下载器上游发布](https://github.com/icloud-photos-downloader/icloud_photos_downloader/releases/tag/v1.33.0) · [飞牛应用框架](https://developer.fnnas.com/docs/core-concepts/framework/) · [飞牛统一网关](https://developer.fnnas.com/docs/core-concepts/gateway-registration/)

在 Linux 或 WSL 的项目目录中构建（Python 3.10 或更新版本）。x86-64 构建机会自动获取固定版本的官方 fnpack，其他架构可用 `--fnpack /path/to/fnpack` 指定本机工具。生成的 FPK 位于 `dist/`。在与飞牛相同的 CPython 3.12 环境运行服务和生命周期测试。运行媒体适配器测试时，将同架构安装包的 `app.tgz` 解开，把其中的 `vendor` 目录加入 `PYTHONPATH`。

```sh
python3 -B build.py
python3.12 -B -m unittest discover -s tests -v
```

## 验证范围

离线测试覆盖原图及实况配对、仅有低画质视频、缺配套视频、同大小损坏文件的识别和修复、RAW 伴随文件、失败后完整补扫，以及账户迁移、并发修改目录、进度恢复、通知凭据、应用启停和打包校验。上游实况样本中，区域列表和照片响应的所有者不一致，原样回放会拒绝归档。仅在测试副本中统一所有者后，3 张 HEIC 和 2 个原版 MOV 均通过了内容校验。独立目录还原后，离线核对通过；改坏其中一个 MOV 后核对失败。用同一组照片模拟只提供低画质视频、只提供静态图两种情形，均得到失败结果。

暂停与继续、分钟级调度、旧账户设置迁移和失败后的完整补查均有离线测试。界面在桌面与手机宽度下用无头浏览器检查过，包括运行记录滚动到底后继续滚动页面。

仍需在目标 NAS 上验证：真实飞牛桌面网关、共享目录 ACL、实际 Apple 账户登录，以及各通知渠道到真实服务的投递。若桌面入口提示网关连接失败，可查看应用数据目录中的 `server.log`。
